# flight-rs

`flight-rs` is a mechanically generated Rust port of the Flight SDK.

The repository deliberately separates durable source from disposable output:

- [`upstream/`](upstream/) pins the authoritative Flight TypeScript source.
- [`tools/generator/`](tools/generator/) analyzes TypeScript, lowers it into a normalized IR, and emits Rust.
- [`generated/`](generated/) is reproducible Rust output.
- [`packages/bitmap-rs/`](packages/bitmap-rs/) is the first explicitly blessed TypeScript-to-wasm facade.
- [`reports/`](reports/) accounts for upstream API coverage and every unsupported source.

The generator architecture is cultivated from [`flighthq/flight-hx`](https://github.com/flighthq/flight-hx): AST and export inventory first, normalized lowering second, deterministic target emission third, and explicit semantic mappings instead of edits to generated files.

## Setup

```sh
git submodule update --init --recursive
npm ci
npm run generate
npm run wasm
npm run check
cargo test --workspace
```

`npm run wasm` installs the pinned Rust target and an exactly matched `wasm-bindgen` CLI when needed, compiles the generated adapter, and bakes synchronous module bytes into the blessed facade. `npm run check` exercises both generator tests and the real wasm facade parity suite.

The compiled target set includes the fully promoted `@flighthq/easing` target, the portable image-resource state slice, the generated bitmap kernel slice, and compiler-checked automatic package candidates. The compatibility-named `@flighthq/bitmap-rs` TypeScript/wasm facade now follows upstream's `@flighthq/bitmap` replacement; its source/declaration selection is cultivated while the `flighthq-surface` crate itself remains generated. It is the only planned standalone wasm package. All other substrate-neutral packages are generated by default; source and declaration blockers remain fingerprinted in [`reports/generation.json`](reports/generation.json), and compiler diagnostics drive each next generator pass.

## Preserved manual port

This repository replaced a handwritten Rust port of the same SDK, preserved read-only at [`flighthq/flight-rs-archive`](https://github.com/flighthq/flight-rs-archive).

That port reached a higher runtime finish than the generated output has today, but it could not be reproduced: every upstream release reopened the whole translation by hand, and stabilizing one area tended to disturb another. This repository trades that finish for repeatability — a mechanical port starts further back and catches up by rule rather than by effort.

The archive is history, not an input to generation. Nothing here reads from it, and a rule that cannot be derived from `upstream/` does not belong in `tools/generator/` because the archive happened to solve it a particular way.
